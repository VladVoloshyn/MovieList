# MovieList

## Предметна область

MovieList — застосунок для ведення власного списку фільмів. Користувач може додавати фільми до колекції, переглядати інформацію про них та відмічати переглянуті фільми.

## Користувач

Користувачем застосунку є людина, яка хоче зберігати та впорядковувати список фільмів для перегляду.

## Основні сценарії

- додавання нового фільму до колекції;
- перегляд списку доданих фільмів;
- позначення фільму як переглянутого;
- отримання списку непроглянутих фільмів;
- додавання та перегляд нотаток до фільмів.

## Основні сутності

### Movie

Представляє окремий фільм та містить інформацію про його назву, рік випуску, жанр, статус перегляду та нотатку.

### MovieCollection

Представляє колекцію фільмів та забезпечує роботу зі списком: додавання фільмів, пошук, зміну статусу перегляду та отримання потрібних фільмів.
# Practical Work 2

## Обрана архітектура

Для проєкту MovieList обрано архітектуру **MVVM (Model-View-ViewModel)**.

MVVM підходить для цього проєкту, оскільки дозволяє чітко розділити:

- **Model** — дані предметної області;
- **View** — відображення інтерфейсу;
- **ViewModel** — логіку представлення та взаємодію з даними.

Такий підхід зменшує зв’язність компонентів, спрощує тестування та дозволяє змінювати реалізацію джерела даних без переписування UI.

## Схема взаємодії компонентів

```text
ContentView
    ↓
MovieListViewModel
    ↓
MovieRepositoryProtocol
    ↓
MovieCollectionAdapter
    ↓
MovieCollection
```

Додатково `MovieListViewModel` використовує окрему стратегію сортування:

```text
MovieListViewModel
    ↓
MovieSortingStrategy
    ├── SortByTitleStrategy
    ├── SortByRatingStrategy
    └── SortByYearStrategy
```

## Розподіл відповідальності

- `Movie.swift` — модель одного фільму.
- `ContentView.swift` — представлення даних користувачу.
- `MovieListViewModel.swift` — логіка представлення та взаємодія з репозиторієм.
- `MovieRepositoryProtocol.swift` — абстракція доступу до даних.
- `MovieCollection.swift` — базова реалізація зберігання колекції.
- `MovieCollectionAdapter.swift` — адаптація `MovieCollection` до нового інтерфейсу репозиторію.
- `MockMovieRepository.swift` — тестова реалізація джерела даних.
- `MovieBuilder.swift` — побудова об’єктів `Movie`.
- `MovieSortingStrategy.swift` — різні способи сортування фільмів.

## Використані патерни проєктування

| Категорія | Патерн | Компонент | Призначення |
| --- | --- | --- | --- |
| Породжувальний | Builder | `MovieBuilder` | Поетапне та читабельне створення об’єктів `Movie` |
| Структурний | Adapter | `MovieCollectionAdapter` | Адаптація `MovieCollection` до `MovieRepositoryProtocol` |
| Поведінковий | Strategy | `MovieSortingStrategy` | Можливість змінювати алгоритм сортування без зміни ViewModel |

### Builder

Патерн **Builder** використовується для зручного створення об’єктів `Movie`.

Приклад:

```swift
let movie = MovieBuilder()
    .setTitle("Interstellar")
    .setYear(2014)
    .setGenre(.sciFi)
    .setRating(8.7)
    .build()
```

Завдяки цьому створення об’єкта стає більш читабельним і не потребує використання довгого конструктора.

### Adapter

`MovieCollectionAdapter` реалізує `MovieRepositoryProtocol` та використовує всередині існуючий `MovieCollection`.

Це дозволило не переписувати код першої практичної роботи, а підключити старий компонент до нової архітектури.

### Strategy

Патерн **Strategy** використовується для зміни способу сортування фільмів.

Реалізовані стратегії:

- сортування за назвою;
- сортування за рейтингом;
- сортування за роком.

Під час виконання програми стратегія може змінюватися без зміни `MovieListViewModel`.

## SOLID

### S — Single Responsibility Principle

Кожен компонент має одну основну відповідальність:

- `Movie` зберігає дані фільму;
- `MovieCollection` працює з колекцією;
- `MovieListViewModel` містить логіку представлення;
- `ContentView` відповідає за UI;
- `MovieBuilder` створює об’єкти `Movie`;
- `MovieSortingStrategy` відповідає за алгоритм сортування.

Таким чином, великий клас із надмірною кількістю обов’язків не створюється.

### O — Open/Closed Principle

Система відкрита для розширення, але закрита для зміни існуючого коду.

Наприклад, для додавання нового способу сортування достатньо створити новий клас, який реалізує `MovieSortingStrategy`. При цьому змінювати `MovieListViewModel` не потрібно.

### L — Liskov Substitution Principle

Будь-яку реалізацію `MovieRepositoryProtocol` можна використати там, де очікується цей протокол.

Наприклад:

- `MovieCollectionAdapter`;
- `MockMovieRepository`.

`MovieListViewModel` працює однаково з обома реалізаціями.

### I — Interface Segregation Principle

`MovieRepositoryProtocol` містить тільки ті методи, які потрібні ViewModel:

- отримання фільмів;
- додавання фільму;
- зміна стану перегляду.

Компоненти не змушені реалізовувати зайві методи.

### D — Dependency Inversion Principle

`MovieListViewModel` залежить не від конкретного класу `MovieCollection`, а від абстракції `MovieRepositoryProtocol`.

Це дозволяє легко замінити реальну реалізацію репозиторію на тестову.

## Dependency Injection

Залежності передаються в `MovieListViewModel` через ініціалізатор:

```swift
MovieListViewModel(
    repository: adapter,
    sortingStrategy: SortByTitleStrategy()
)
```

Для тестування можна передати:

```swift
MovieListViewModel(
    repository: MockMovieRepository(),
    sortingStrategy: SortByTitleStrategy()
)
```

При цьому код `MovieListViewModel` не змінюється.

## Перевірка заміни залежності

У проєкті реалізовано `MockMovieRepository`, який також відповідає протоколу `MovieRepositoryProtocol`.

Під час перевірки основний `MovieCollectionAdapter` був замінений на `MockMovieRepository`, після чого сценарій продовжив працювати без змін у `MovieListViewModel`.

Це демонструє використання **Dependency Injection** та **Dependency Inversion**.

## Перевірка на антипатерни

У проєкті було перевірено такі можливі проблеми:

- надмірна відповідальність одного класу;
- дублювання логіки;
- приховані глобальні залежності;
- пряме поєднання UI з доступом до даних.

У результаті:

- UI не працює напряму з `MovieCollection`;
- View використовує `MovieListViewModel`;
- ViewModel залежить від абстракції `MovieRepositoryProtocol`;
- залежності передаються через ініціалізатор;
- логіка створення та сортування винесена в окремі компоненти.

Таким чином вдалося уникнути **God Object**, жорсткої зв’язності та прихованих залежностей.

# Практична робота №4

## Мета роботи

Метою роботи було інтегрувати реальне серверне джерело даних у застосунок MovieList, організувати окремий мережевий шар, виконати асинхронний HTTP-запит, перетворити отриманий JSON у типізовані Swift-моделі та відобразити в інтерфейсі стани завантаження, успішного результату, порожньої відповіді та помилки.

У практичній роботі було продовжено розвиток застосунку MovieList, створеного у попередніх роботах.

## Джерело даних

Для отримання реальних серверних даних було використано відкрите API **TVmaze**.

Базова адреса API:

`https://api.tvmaze.com`

Для пошуку фільмів і серіалів використовується endpoint:

`/search/shows`

HTTP-метод:

`GET`

Основний параметр запиту:

`q`

Параметр `q` містить текст пошукового запиту користувача.

Приклад запиту:

`https://api.tvmaze.com/search/shows?q=Dark`

Для цього endpoint авторизація не потрібна. API не потребує API key або access token.

Формат відповіді:

`JSON`

API повертає масив результатів пошуку. Кожний результат містить коефіцієнт відповідності `score` та об'єкт `show` з інформацією про знайдений серіал або шоу.

У застосунку використовуються такі дані:

- `id` — ідентифікатор;
- `name` — назва;
- `premiered` — дата прем'єри;
- `genres` — список жанрів;
- `rating` — рейтинг;
- `summary` — короткий опис.

## Типізовані моделі відповіді

Для перетворення JSON-відповіді у Swift-об'єкти було створено окремі моделі:

- `TVMazeSearchResult`;
- `TVMazeShow`;
- `TVMazeRating`.

Моделі реалізують протокол `Decodable`.

```swift
struct TVMazeSearchResult: Decodable {
    let score: Double
    let show: TVMazeShow
}

struct TVMazeShow: Decodable {
    let id: Int
    let name: String
    let premiered: String?
    let genres: [String]
    let rating: TVMazeRating
    let summary: String?
}

struct TVMazeRating: Decodable {
    let average: Double?
}
```

Отримані від сервера дані декодуються за допомогою `JSONDecoder`:

```swift
return try JSONDecoder().decode(
    [TVMazeSearchResult].self,
    from: data
)
```

Якщо структура отриманого JSON не відповідає структурі типізованих моделей, генерується помилка декодування.

## Мережевий компонент

Для роботи із серверним API було створено окремий компонент:

`MovieAPIService`

Мережевий сервіс відповідає за:

- формування URL;
- додавання параметрів запиту;
- створення HTTP-запиту;
- виконання запиту;
- отримання відповіді;
- перевірку HTTP-статусу;
- декодування JSON;
- перетворення помилок у зрозумілі типи.

Для виконання HTTP-запиту використовується стандартний компонент Apple:

`URLSession`

Запит виконується асинхронно:

```swift
(data, response) = try await session.data(for: request)
```

Завдяки використанню `async/await` очікування відповіді від сервера не блокує інтерфейс користувача.

## Абстракція мережевого сервісу

Для того щоб компоненти застосунку не залежали безпосередньо від конкретної реалізації мережевого сервісу, було створено протокол:

```swift
protocol MovieAPIServiceProtocol {
    func searchShows(query: String) async throws -> [TVMazeSearchResult]
}
```

Реальний клас:

`MovieAPIService`

реалізує `MovieAPIServiceProtocol`.

Завдяки використанню протоколу реальний сервіс можна замінити тестовою або mock-реалізацією без зміни ViewModel або користувацького інтерфейсу.

Це також дозволяє керовано відтворювати негативні сценарії та перевіряти обробку помилок.

## Repository для серверних даних

Для відокремлення серверних моделей TVmaze від внутрішньої моделі застосунку було створено:

`MovieNetworkRepository`

Також використовується абстракція:

```swift
protocol MovieNetworkRepositoryProtocol {
    func searchMovies(query: String) async throws -> [Movie]
}
```

`MovieNetworkRepository` отримує дані через `MovieAPIServiceProtocol`, після чого перетворює серверні моделі у внутрішню модель `Movie`.

Під час перетворення:

- із `premiered` отримується рік;
- серверний жанр перетворюється у `MovieGenre`;
- використовується рейтинг TVmaze;
- HTML-теги видаляються з поля `summary`;
- формується звичайний об'єкт `Movie`.

Таким чином, решта застосунку не залежить від внутрішнього формату TVmaze API.

## NetworkMovieViewModel

Для керування станом мережевого екрану було створено окремий:

`NetworkMovieViewModel`

Він отримує залежність через ініціалізатор:

```swift
init(repository: MovieNetworkRepositoryProtocol) {
```

Таким чином, ViewModel працює з абстракцією, а не з конкретним класом repository.

ViewModel оголошено як:

Використання `@MainActor` гарантує, що зміни стану, які впливають на SwiftUI, виконуються на головному actor.

Реальний мережевий запит виконується асинхронно:

```swift
let movies = try await repository.searchMovies(

```

## Обробка мережевих помилок

Для розділення різних типів відмов створено:

```swift
enum NetworkError: LocalizedError {
    case invalidURL
    case transport(Error)
    case invalidResponse
    case httpError(Int)
    case decoding(Error)
}
```

### Transport error

Транспортна помилка означає, що HTTP-відповідь від сервера не була нормально отримана.

Прикладами є:

- відсутність інтернет-з'єднання;
- timeout;
- проблема DNS;
- недоступність сервера.

У коді вона представлена як:

```swift
case transport(Error)
```

При виникненні помилки під час `URLSession` вона перетворюється на:

```swift
do {
    (data, response) = try await session.data(for: request)
} catch {
    throw NetworkError.transport(error)
}
```

### HTTP-помилка

HTTP-помилка означає, що зв'язок із сервером відбувся, але сервер повернув неуспішний HTTP-статус.

Наприклад:

- `404`;
- `500`;
- `503`.

Перед декодуванням JSON обов'язково перевіряється HTTP-код:

```swift
guard (200...299).contains(httpResponse.statusCode) else {
    throw NetworkError.httpError(
        httpResponse.statusCode
    )
}
```

Таким чином, відповідь із неуспішним HTTP-кодом не обробляється як коректний результат.

### Decoding error

Помилка декодування виникає, якщо отриманий JSON не відповідає очікуваній структурі `Decodable`-моделей.

Обробка виконується так:

```swift
do {
    return try JSONDecoder().decode(
        [TVMazeSearchResult].self,
        from: data
    )
} catch {
    throw NetworkError.decoding(error)
}
```

Він реалізує той самий протокол:

`MovieAPIServiceProtocol`

```swift
enum Mode {
    case success
    case empty
    case error
}
```

Для перевірки негативного сценарію використовується:

```swift

throw NetworkError.transport(
```

## Dependency Injection

Мережеві залежності передаються ззовні.

Створюється реальний API-сервіс:

```swift
let apiService = MovieAPIService()
```

Після цього він передається в repository:

```swift
let networkRepository = MovieNetworkRepository(
    apiService: apiService
)
```

Repository передається у ViewModel:

```swift
let networkViewModel = NetworkMovieViewModel(
    repository: networkRepository
)
```

Це дозволяє замінити реальну реалізацію на mock без зміни `NetworkMovieViewModel` або `NetworkMovieSearchView`.
